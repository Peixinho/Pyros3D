# 2D in Pyros3D

What the engine and the editor give a 2D game, and how the pieces fit. The
worked example is `projects/Toybox2D`: every tool below is in that one level,
and `tools/build_scene.py` there builds it through the editor's commands.

A 2D scene is an ordinary scene marked 2D (File > New Scene > 2D). It lies in
the XY plane, y up, and is drawn through an orthographic view; z is draw
order. It needs no camera object - see [The view](#the-view).

## Sprites

A **sprite sheet** (`.p3ds`) says how one image is cut into frames and which
runs of frames are clips. It sits beside the image. The image stays one
texture; a frame is a rectangle of it.

- Make one: right-click an image in Assets > **Create Sprite Sheet…**, or
  `create_spritesheet`. Cut it as a grid (by cell size or by count), round
  the opaque islands of the image (Automatic), or import an Aseprite /
  TexturePacker JSON.
- Per sheet: **pixels per unit** (a 32 px frame at 32 is one unit tall), the
  filter (Nearest for pixel art), and an optional **normal map** - an image
  laid out exactly like the sheet's (green is up). Lit sprites are then
  shaded by which way each texel faces a light, and the light's z is its
  height above the plane.
- **Packing loose images**: right-click a folder in Assets > **Pack Images
  into Sprite Atlas**, or `pack_sprite_atlas`. Every image in the folder is
  trimmed and laid out in one picture named after the folder, with a sheet:
  a frame per file, and a clip for every numbered run (`walk_0`, `walk_1`...).
  Run it again after adding a frame; pivots, borders and clips are kept by
  frame name.
- Per frame: a name, a **pivot** (normalised, y up - `[0.5, 0]` is
  bottom-centre), **nine-slice borders**, and an optional hold time.
  With one frame selected in the sprite sheet editor, drag its corners and
  sides to resize it, its body to move it, and the red dot to place its
  pivot; everything lands on whole pixels.
- Clips: a name, a list of frames, a rate, loop / ping-pong, and named
  **events** on steps of the clip.

A **Sprite2D** component draws one frame of a sheet (or a whole image, which
is a sheet of one frame). Add > Sprite, drop an image or a `.p3ds` on the
Scene View of a 2D scene, or `add_sprite`.

| Property | |
| --- | --- |
| Source, Frame | which sheet and which frame |
| Flip X / Y, Colour | in the sprite's vertices: tinting one never costs another draw call |
| Draw Mode | Simple (its own size), Sliced (nine-slice to Size), Tiled (repeated to Size) |
| Pixels Per Unit | 0 uses the sheet's |
| Own Pivot | replaces the frame's pivot for this sprite |
| Lighting | Unlit (the art exactly), 2D lighting, 3D lighting |
| Blend | Alpha, Additive, Premultiplied |
| Sort Order | drawn over every lower order whatever its z; among equals z decides |
| Plays, Speed | the clip it starts on |

| Material | a `.mat` in place of the sprite's own, for what Lighting and Blend cannot say; it names its own textures |
| Mask | shown only inside, or only outside, a Sprite Mask |

A **SpriteBatch2D** on a parent draws every sprite beneath it in one call
per run of sprites sharing a texture. Four thousand unlit sprites measured
4,011 draws (about 13 ms of scene render) without and 12 draws with. A batch
nothing in changed costs nothing; one that changes re-merges that frame.

Lit sprites are merged too, cut into cells (**Light Cell**, 8 units by
default): lighting picks at most four lights for each thing drawn, so one
mesh over a whole level would be lit by the four nearest its middle, where a
cell is lit by the lights near it. Six hundred lit sprites under twelve
lights measured 431 draws without and 26 with, pixel for pixel the same.
Keep a cell no bigger than the gap between lights.

A frame's texture coordinates stop a little inside its rectangle so that it
never samples its neighbour. How far is the sheet's **edge inset**: half a
texel for smoothly filtered frames packed edge to edge, next to nothing for
Nearest filtering and for packed atlases, whose frames have clear padding.

```lua
local s = hero:getComponent("Sprite2D")      -- or Sprite2D.new("assets/textures/hero.p3ds")
s:play("run")                                -- leaves a clip already playing alone
s:play("attack", true)                       -- restart
s:setFlipX(vx < 0)
s:setColor(1, 0.4, 0.4, 1)                   -- or s:setAlpha(a)
s:setFrame("hero_3")                         -- by name or index; stops the clip
s.onEvent = function(name) end               -- a clip's named events
s.onFinished = function(clip) end            -- a one-shot clip ended
```

Also: `setDrawMode`, `setSize`, `setPivot`, `setLighting`, `setBlend`,
`setSortOrder`, `setSpeed`, `getClips`, `getClip`, `isPlaying`,
`getLocalRect`, `load(path)`, `setMaterial(path)`,
`setMaskInteraction(SpriteMask.Inside)`, `setMaskName(name)`.

### Masks

A **SpriteMask2D** is a shape - a rectangle, a circle, a convex polygon -
or the opaque part of an **image** (any silhouette, laid over the mask's
size) - that sprites are shown only inside of, or only outside of: a window,
a porthole, a bar that empties from one end. It draws nothing itself. Put it
on the parent of what it cuts and set each sprite's **Mask** to Inside or
Outside; or name any mask object on the sprite. Its edge is hard - there is
no soft, part-transparent mask: sprites are cut to the shape before they are
drawn, which is why it is the same on every backend and works inside a batch.
An image is read at no finer than 128 cells a side.

To hide a sprite, `sprite:setVisible(false)`. A sprite's mesh is made by the
sprite and is not something a script can ask the object for; a game that hid
its old quad sprites by disabling their RenderingComponent hides them this
way once they are Sprite2D.

A mask's edge is hard unless it has a **Soft Edge** (`feather`, in the
scene's units): the width, in from the outline, over which what it shows
fades out. Rectangles, circles and polygons; an image's silhouette stays
hard. `add_sprite_mask {..., "feather": 0.5}`, `mask:setFeather(0.5)`.

### Lines and trails

A **Line2D** is a line with width through a list of points - a rope, a
laser, an outline - whose width and colour can run from one value at its
start to another at its end. Set to **Trail**, it is instead the path its
object has just taken: a point laid down each so far, fading and thinning
over its lifetime. It can carry an **image** along its length - a rope's
strands, a chain's links - stretched once or repeated every so far. One draw
call a line; a trail only runs while the game does. It cannot share an
object with a sprite - put it on a child. `line:setPoint(i, x, y)` moves one
point, which is all a rope between two moving things needs each frame.

```lua
local t = Line2D.new()
t:setTrail(true)   t:setTrailLifetime(0.4)   t:setWidth(0.3, 0)
t:setColors(Vec4.new(1, 1, 0.3, 1), Vec4.new(1, 0.2, 0, 1))   t:setAdditive(true)
bullet:addComponent(t)
```

Scenes made before Sprite2D hold sprites as textured quads with a folder of
per-frame PNGs. **Convert to Sprite2D** in Properties, or `convert_sprites`,
turns them into sprites that look the same.

## Physics

`Physics2D` is a Box2D body.

- **Body**: Static, Kinematic (moved by script, pushes others), Dynamic.
- **Shape**: Box, Circle, **Capsule** (what a character wants), **Polygon**
  (a solid outline of any shape - one that is not convex is cut into convex
  pieces for the solver) and **Chain** (a line of edges with no inside,
  open or closed: hand-drawn ground and walls; no mass, so for a Static or
  Kinematic body), with an **Offset** from the object's origin. *Fit to
  Sprite* sizes and places it over the object's sprite.
  Tick **Edit Collider** for handles on the shape in the Scene View: a side
  resizes it from that side, the centre moves it, a polygon's points move
  one at a time; Ctrl snaps to a quarter unit. On a polygon or a chain,
  Shift-click an edge adds a point and Alt-click a point removes it. The
  same edit from outside the editor is `drag_collider2d`. A body is also a
  row of its own in the Scene Tree (**Body 2D**, under its object):
  selecting that row is editing its collider.
- Density, friction, bounciness, **gravity scale**, linear / angular damping,
  fixed rotation, **bullet**.
- **Sensor**: collides with nothing and reports who is inside it.
- **One-Way Platform**: solid from above, open from below and the sides.
- **Collision layers**: a body is on one layer (0-31) and collides with the
  layers in its mask.

The scene's gravity is in the Game View settings (`gravity2D` in the file).

```lua
local b = hero:getComponent("Physics2D")
b:setLinearVelocity(vx, vy)        b:applyImpulse(x, y)
b:isGrounded()                     -- standing on something
b:getGroundNormal()                b:getGroundBody()
b:getGroundVelocity()              -- add it to ride a moving platform
b:moveTo(Vec2.new(x, y), angle, dt)   -- drive a kinematic body; carries riders
b:setCollidesWith(layer, false)    -- e.g. drop through one-way platforms
b.onCollisionEnter = function(other) end
b.onContact = function(other, point, normal, speed) end
b.onTriggerEnter = function(other) end      -- sensor and visitor both hear it
```

Moving the *object* of a body (`go:setPosition`) moves the body with it.

The world is the global `physics2d`:

```lua
local hit = physics2d:rayCast(from, to, ignoreBody)       -- hit.point, .normal, .fraction, .component
physics2d:rayCastAll(from, to)          physics2d:circleCast(from, to, radius)
physics2d:boxCast(from, to, halfExtents, angle)
physics2d:overlapPoint(p)               physics2d:overlapCircle(c, r)
physics2d:overlapBox(c, halfExtents, angle)
physics2d:setGravity(0, -40)
```

Every query takes an optional layer mask; rays and casts never stop on a
sensor.

### Joints

`Joint2D` goes on the object that moves, next to its body, and names the
object it is tied to - or nothing, to be pinned to the world.

| Kind | | Useful settings |
| --- | --- | --- |
| Hinge | turns about a pin: a door, a pendulum | limits (degrees), motor, spring |
| Distance | a rod, a rope, a spring | length, min / max, spring |
| Weld | glued together | spring for a connection that gives |
| Slider | moves along an axis: a lift, a piston | limits, motor |
| Wheel | a slider that also turns | spring, motor |
| Target | pulled towards a point a script sets: dragging with the mouse | spring (how eagerly), max force |
| Ignore | the two bodies do not collide with each other | |
| Pulley | a rope over two fixed world points: what one side gives the other takes | the two points, ratio |
| Gear | two turning bodies turn together, opposite ways | ratio |

Limits are measured from how the two bodies stand when Play starts. A
Distance joint with no far anchor given runs to the other body's origin.
`joint:setMotorSpeed(v)` changes a running motor without rebuilding it, and
`joint:setTarget(x, y)` moves a Target's point.

A joint can **break**: give it a break force (`Breaks At` in the panel,
`breakForce` in `add_joint2d`, `joint:setBreakForce(n)`) and, asked to hold
more than that, it is undone - a plank that drops when stood on, a chain
that snaps. `joint.onBreak = function() end` hears it, `joint:isBroken()`
asks, and `joint:mend()` makes it again.

An object holds one joint. For a second on the same body - a wheel that is
hinged and geared - put it on a child with no body of its own: such a joint
ties the nearest body above it.

The solver has no pulley and no gear, so the engine holds those two itself,
once a step. They carry lifts, counterweights and clockwork; a pulley at
the bottom of a tall stack of things that are also wedged against each
other is softer than a solver joint would be.

A body can be **one-way** (solid from above only: walked past, jumped up
through, stood on). That holds for a tile map's body too - a bridge painted
in tiles on a map of its own, with a one-way body, is the usual platform.

## The view

A 2D scene frames itself: Properties with the scene root selected > **Game
View**, or `set_game_view_2d`.

Centre and zoom; **follow** an object by name with a lag, per axis, with an
offset; **bounds** the view's edge stops at; a **dead zone** the followed
object can move in without the view moving; **look-ahead** in the direction
it moves; **pixel snap**.

```lua
view.follow("Hero", 0.15)          view.setBounds(minX, minY, maxX, maxY)
view.setDeadZone(1, 0.6)           view.setLookAhead(2, 0)
view.shake(0.3, 0.4)               view.zoomTo(4, 0.5)
view.setPixelPerfect(16, 3)        -- 16 px/unit drawn at exactly 3x
local x, y = view.mouseWorld()     view.screenToWorld(px, py)
local l, b, r, t = view.visibleRect()
```

The editor's Play and a built game run the same code for all of it.

## Layers and parallax

`Layer2D` on a parent makes its subtree a layer: its z is the draw order and
its parallax factor how fast it crosses the screen (1 with the level, 0.5
half speed, 0 pinned). Tick **Automatic** and the engine scrolls it as the
view moves; scenes made earlier scroll their layers from script and are left
alone.

## Ground with depth: Extrusion 2D

`Extrusion2D` is an outline drawn in the plane of the screen and given depth:
ground to ride over, a platform, a wall, a ramp - the 3D shape of a 2D (or
2.5D) level, and the collider that goes with it. Add Component > **Extrusion
2D**, or `add_extrusion2d`.

- **Open** (the default), the points are the top of the shape and it goes
  down to **Floor**: ground. **Closed**, they are the whole shape: a block.
- **Smooth** curves each stretch between two points into that many pieces;
  the points stay what you edit, the curve is what is drawn and collided with.
- It is drawn as two surfaces, each with its own image repeated every
  **Tile** units: the skin (what is walked on) and the faces (the cut ends).
  Both are ordinary lit, shadowed meshes and take any material.
- With **Collider follows the outline** on, the object's Physics 2D body is
  kept as a chain along the curve, so what is touched is what is seen.

**Edit Outline** in its panel puts the points in the view, in a 2D scene or a
3D one: drag a point; Shift-click on the line to add one there (or past an
end to carry it on); Alt-click one to remove it. Each is one undo step.

```lua
local ground = scene:find("Ground"):getComponent("Extrusion2D")
local y = ground:heightAt(x)                -- an open outline's height at x, in its own space
ground:setPoint(3, x, y)  ground:apply()    -- the shape and its collider, changed while playing
```

Commands: `add_extrusion2d` / `set_extrusion2d {object, points, closed,
smooth, depth, floor, tile, skin, face, skinColor, faceColor, collider}`,
`extrusion2d_info`, `edit_extrusion2d {object, on}`, `drag_extrusion2d
{object, index + to | add (+at) | remove}`.

## Particles that land

A particle system with **Collide (2D)** on stops at the bodies of the 2D
world: sparks that bounce along a floor, rain that ends at a roof.
**Bounce** is how much speed into the surface a particle keeps. Each
particle is a ray a frame, so it is for tens or hundreds of them; a
GPU-simulated system ignores it. `ps:setCollide2D(true, 0.4)`,
`"collide2D": true, "bounce": 0.4` in `add_particles`.

## Light and shadow

Sprites and tile maps set to 2D lighting are lit by point and spot lights by
distance. `Occluder2D` (or any body with Casts 2D Shadow) blocks light. Up to
64 segments are on screen at once - a box is 4, a circle 8 - spent on the
shapes nearest the lights in view, so the length of a level does not matter.

## Tile maps and characters

`TileMap2D` (a `.p3dt` tile set painted into a scene - **B** in the Scene
View) is described in `TILEMAP_PLAN.md`.

A map answers "how do I get there":

```lua
-- wherever a cell is open (top-down): a list of {x, y} cells, or nil
local way = map:findPath(x0, y0, x1, y1)
-- for something that walks (side-on): it stands on solid cells, steps,
-- jumps and drops. Each entry is {x, y, move = "start"|"walk"|"jump"|"drop"}
local steps = map:findWalkPath(x0, y0, x1, y1, { jump = 3, distance = 3, drop = 8, height = 1 })
local cx, cy = map:worldToTile(Vec2.new(localX, localY))      -- and map:tileToWorld(cx, cy) back
```

For many searches a frame, `PathGrid` runs them on the job system;
`TileMap2D::BuildPathCosts` hands it the map. A cut-out character with bones and
keyed clips is a `.p3d2d` asset built in the 2D Character editor (New 2D
Character in the Assets panel's menu) and placed in a scene like any other
asset.

### Terrains: a map that picks its own corners

A tile set can say that sixteen tiles in a row are one **terrain**: one tile
for each way a cell's four neighbours can be the same terrain or not (bit 0
the cell above, 1 to the right, 2 below, 3 to the left - so tile 0 stands
alone and tile 15 is surrounded). Painting with a terrain
(`paint_terrain {object, group, cells}`, or the terrain brush) puts down
cells and the map chooses each one's tile, and re-chooses its neighbours'.
`edit_tileset {"terrain": {"base": 16, "name": "grass"}}` declares one.

`tilemap_path {object, from, to, walk, jump, distance, drop, height}` asks
the editor the same question `findPath` / `findWalkPath` answer in a game,
to check a level can be crossed before playing it.

## Words

`Text2D` is text in the world: an object's own words, in the scene's units,
with an anchor - a sign, a name over a head, a number that floats up off a
pickup. `add_text2d {object, font, text, size, color, anchor}`;
`Text2D.new(fontPath, text, size)`, `setText`, `setColor`, `setAlpha`,
`setSize`, `setAnchor`. (UI text on a canvas is for the screen; this is for
the level.)

Text is UTF-8 in and draws ASCII and the accented Latin letters (U+00A1 to
U+00FF). Anything else is drawn as `?`.

A game's words by key, in more than one language:

```lua
lang.loadBest({ "en", "pt" })      -- the device's language if there is a file for it: assets/lang/<code>.json
lang.load("pt")                    -- or one by name
tr("level", 3)                     -- "Level {1}" -> "Level 3"
lang.apply(scene)                  -- every text authored "@key" (UI and Text2D) is given its words
```

## Easing

`tween` moves a value over a time; the engine runs them, a script only
starts them. Eases: `linear`, `in`, `out`, `inout`, `back`, `bounce`,
`elastic`. Every call returns a handle `tween.cancel` takes, and takes a
function to call when it is done.

```lua
tween.move(go, x, y, 0.4, "out")           tween.scale(go, 1.5, 0.2, "back")
tween.rotate(go, angle, 0.3)               tween.alpha(sprite, 0, 0.25, "in", function() ... end)
tween.tint(uiElement, r, g, b, a, 0.3)     -- a full-screen black image eased to clear is a fade
tween.value(0, 100, 1.0, "out", function(v) ... end)
tween.after(0.5, function() ... end)       tween.clear()
```

## Input

```lua
isKeyDown(Key.A)                   isMouseButtonDown(button)
gamepad.isConnected(0)             gamepad.axis(0, GamepadAxis.LeftX)   -- sticks read +1 up / right
gamepad.isDown(0, GamepadButton.A)
```

On a touch screen the first finger also moves the pointer, so anything
written for a mouse works. A game held in two thumbs needs every finger:

```lua
touch.count()                                  -- fingers down
local id, x, y, began, ended = touch.get(1)
local scale, cx, cy, dx, dy, turn = touch.pinch()   -- two fingers: nil with fewer
ui.isHeld(scene, button)                       -- any finger (or the pointer) is on this element
local x, y, held = ui.stick(scene, pad)        -- the element as a thumb stick, -1..1, up positive
```

## Sound

`Sound.new(path, voices)` and `AudioSource` play WAV, MP3, FLAC and Ogg
Vorbis. The mix is limited before it reaches the device, so a dozen sounds
at once do not clip.

## Laying out a level in the editor

- **Edit > Snap** sets a step for each gizmo - move, rotate (degrees),
  scale - in 2D and 3D scenes alike. With a step off, holding Ctrl while
  dragging snaps for as long as it is held (1 unit, 15 degrees, 0.1).
  `set_snap {move, rotate, scale}`.
- **Duplicate** with a move step on sets the copy one step to the right.
  `duplicate {name, offset: [x, y, z], count}` makes a row.
- A prefab dragged from Assets into a 2D view lands in the middle of what
  the view shows, on the step.

## Other helpers

`scene:find("Name")` returns the object of that name anywhere in the tree.
